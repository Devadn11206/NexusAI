# NEXUS AI: Security Policy & Isolation Specification

## 1. Overview
NEXUS AI is an autonomous agent system designed to manipulate local files, execute terminal commands, and integrate with external APIs. Because remote messaging platforms (Telegram & WhatsApp) are inherently public-facing, rigorous security gates must prevent arbitrary code execution by unauthorized parties and avoid destructive host operations.

---

## 2. Security Gatekeeper & Ingress Whitelisting

### 2.1 Threat Model
- Unsolicited messages, spam bots, and malicious actors targeting public Telegram Bot handles or WhatsApp Webhook endpoints.
- Injection attacks via messaging prompts trying to bypass agent instructions.

### 2.2 Gatekeeper Mechanism
1. **Immediate Verification (Fast-Fail)**:
   - Every incoming Webhook request from Telegram or WhatsApp is inspected before reaching any agent dispatcher, task queue, or database transaction.
   - For Telegram: `from.id` (chat ID) is verified against `ALLOWED_TELEGRAM_CHAT_IDS`.
   - For WhatsApp: `from` (sender phone number in E.164 format) is verified against `ALLOWED_WHATSAPP_PHONES`.
2. **Instant Drop Policy**:
   - Non-whitelisted senders receive an immediate `403 Forbidden` response (or silent 200 with an empty drop payload depending on channel configuration to prevent bot enumeration).
   - Zero agent cycles, token consumptions, or database rows are created for non-whitelisted entities.
   - Security incidents are logged with the caller identifier and timestamp.

## 3. Workspace Isolation Boundaries

### 3.1 Strict Directory Confinement
- All file creations, reads, edits, downloads, and generated artifacts are strictly confined to the directory `./workspace/`.
- Path traversal vectors (`../`, absolute paths outside `./workspace`, symbolic link dereferences) are blocked by the filesystem abstraction adapter.

```python
import os
from pathlib import Path

WORKSPACE_ROOT = Path("./workspace").resolve()

def resolve_safe_path(target_path: str) -> Path:
    resolved = (WORKSPACE_ROOT / target_path).resolve()
    if not resolved.is_relative_to(WORKSPACE_ROOT):
        raise PermissionError(f"Access denied: Path '{target_path}' attempts to escape workspace sandbox.")
    return resolved
```

### 3.2 Human-in-the-Loop (HITL) Triggers
Certain sensitive operations cannot proceed automatically:
- Shell commands (`rm -rf`, `sudo`, package installations, network scans).
- Exfiltration of private key files or `.env` variables.
- System-level configuration updates.

When these actions are generated by an agent node:
1. `hitl_approval_required` is toggled to `true`.
2. The LangGraph run transitions to `AWAITING_APPROVAL`.
3. The exact command and predicted impact are sent as an interactive prompt to the authorized Telegram/WhatsApp user.
4. Execution halts until an explicit confirmation command (`/approve <task_id>` or `/reject <task_id>`) is submitted.
